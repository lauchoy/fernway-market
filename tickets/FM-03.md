TICKET: FM-03  Data generator and `month_small` fixture

GOAL: `--seed 42` reproduces byte-identical files, and `month_small` ships with a hand-verified `expected.csv` for Jimmy to sign off.

FROZEN AUTHORITIES: SPEC sections 6 (release cases, money as cents), 8 (stages, for what the oracle must show), 9 (rules, `partial_refund_policy: null` in the seed), 14 (synthetic data), 17 (FM-03 row), plus the decisions agreed on 2026-10-01 listed below.

DECISIONS APPLIED (synthetic generator choices, not business rules; recorded in docs/DECISIONS.md):
- Variance direction: funding exceeds releases by exactly 5000 cents. The untyped fee adjustment line is `+5000` with `adjustment_type` empty. Typed adjustments are matched by ADJUSTED releases so they net to zero.
- Refunds arrive as `REFUND` rows inside each storefront export (upload kinds are only storefront_a, storefront_b, funding). Fee adjustments arrive in the funding file.
- Funding lines are keyed by the seller's `payout_token`.
- Draft file layouts, for approval with this ticket:
  - storefront_a CSV: `Row Type, Order Ref, Seller Handle, Gross, Fee, Net, Delivered On, Refund Amount, Refund Kind, Processed On`. `Row Type` is `ORDER` or `REFUND`. Dates `MM/DD/YYYY`, money `$1,234.56`.
  - storefront_b XLSX, sheet `orders`: `row_type, order_ref, merchant_id, gross_cents, fee_cents, net_cents, delivered_at, refund_cents, refund_kind, processed_at`. ISO dates, integer cents.
  - funding CSV: `seller_ref, amount_cents, line_type, adjustment_type`.
- Order amounts, fee percentage and delivery dates are seeded generator parameters, labelled synthetic.
- Fixture cycle: `2026-09`, period end 2026-09-30, 14-day window.
- `expected.csv` is one row per hold with columns `seller_id, order_ref, case, release_cents, residual_cents, block_reason`. The fixture runs with `partial_refund_policy: null`, so PARTIAL rows show `Partial-refund policy not decided - owner: Ops lead`.

IN SCOPE:
- `data/generator/` (Python, stdlib plus `openpyxl` for XLSX, no domain imports), CLI `--seed`, `--size full|small`
- Full run: 3,000 sellers, about 30,000 orders split across both storefronts, injected 12 unmatched aliases, 2 ambiguous aliases, 40 partial refunds, 25 full refunds, 8 fee adjustments (one untyped), funding exactly 5000 cents over releases; writes a `manifest.json` with these counts and the expected release total
- `data/fixtures/month_small/`: 20 sellers, all four cases at least once, input files plus hand-authored `expected.csv` with a worked derivation table in the PR description
- Committed sha256 file for the seed-42 outputs; generator tests

OUT OF SCOPE: ingest or mapping YAML (FM-04), any domain or validation code, fixtures for unmatched or ambiguous aliases in `month_small` (the spec requires only every case), a second rules variant for the decided-policy path, performance tuning.

ACCEPTANCE:
1. Given `--seed 42` run twice, when outputs are hashed, then every file is byte-identical and matches the committed sha256 list.
2. Given the full run, when the manifest is read, then it shows 3,000 sellers, the injected counts above, and funding minus releases equal to 5000 cents.
3. Given `month_small`, when inspected, then it has 20 sellers and contains at least one EXACT, PARTIAL, ZERO and ADJUSTED hold.
4. Given `expected.csv`, when parsed, then it has one row per `month_small` hold with the agreed columns, and each row's release equals the worked derivation in the PR.
5. Given the generator source, when scanned, then money values are ints only (a test fails on any float in money paths).

EVIDENCE: test output; two-run hash comparison; manifest contents; `expected.csv` and the derivation table; `git diff --stat` (fixtures excluded from the 400-line count). Then stop and hand `expected.csv` to Jimmy for sign-off.

STOP IF: spec conflicts with reality, a needed value has no source (for example how an ADJUSTED amount's sign is chosen), two attempts fail, or scope must grow.
